# Frontend UI Engineering

## Overview

Build production-quality user interfaces with NextJS App Router, React Query for server state management, and HeroUI component library. The goal is UI that looks like it was built by a design-aware engineer at a top company — not like it was generated by an AI. This means real design system adherence, proper accessibility, thoughtful interaction patterns, infinite scroll pagination, and no generic "AI aesthetic."

## When to Use

- Building new UI components or pages with NextJS App Router
- Modifying existing user-facing interfaces
- Implementing responsive layouts with HeroUI components
- Adding interactivity with React Query for server state
- Fixing visual or UX issues
- Creating Server Components or Client Components
- Implementing infinite scroll pagination

### Component Patterns

**Server Components vs Client Components:**

```tsx
// Server Component (default) - Passes query params to Client Component
// app/tasks/page.tsx
import { TaskList } from '@/components/TaskList/TaskList';
import { Suspense } from 'react';

export default function TasksPage({ searchParams }: { searchParams: Promise<{ page?: string }> }) {
  const initialPage = Number((await searchParams).page) || 1;
  
  return (
    <div>
      <h1 className="text-2xl font-bold mb-6">My Tasks</h1>
      <Suspense fallback={<TaskListSkeleton />}>
        <TaskList initialPage={initialPage} />
      </Suspense>
    </div>
  );
}

// Client Component - Uses React Query for infinite scroll
// components/TaskList/TaskList.tsx
'use client';

import { useInfiniteQuery } from '@tanstack/react-query';
import { Card, CardBody } from '@heroui/card';
import { Spinner } from '@heroui/spinner';
import { Button } from '@heroui/button';
import { fetchTasks } from '@/lib/api';
import { TaskItem } from './TaskItem';

export function TaskList({ initialPage }: { initialPage: number }) {
  const {
    data,
    fetchNextPage,
    hasNextPage,
    isFetchingNextPage,
    isLoading,
    error,
  } = useInfiniteQuery({
    queryKey: ['tasks'],
    queryFn: ({ pageParam = 1 }) => fetchTasks({ page: pageParam, limit: 10 }),
    initialPageParam: initialPage,
    getNextPageParam: (lastPage, allPages) => {
      return lastPage.length === 10 ? allPages.length + 1 : undefined;
    },
  });

  if (isLoading) return <TaskListSkeleton />;
  if (error) return <div>Error loading tasks</div>;

  const tasks = data?.pages.flat() || [];

  return (
    <Card>
      <CardBody className="p-0">
        <ul role="list" className="divide-y divide-default">
          {tasks.map(task => (
            <TaskItem key={task.id} task={task} />
          ))}
        </ul>
        
        {hasNextPage && (
          <div className="p-4 flex justify-center">
            <Button
              isLoading={isFetchingNextPage}
              onPress={() => fetchNextPage()}
              variant="flat"
              color="primary"
            >
              Load More
            </Button>
          </div>
        )}
      </CardBody>
    </Card>
  );
}
```

## State Management in NextJS

**Choose the right approach:**

```
useState                     → Local UI state (Client Components only)
useReducer                   → Complex local state
URL state (searchParams)     → Filters, shareable state (preferred)
Context                      → Theme, auth (read-heavy, write-rare)
React Query                  → Server state caching, infinite queries (recommended)
Zustand/Redux                → Complex client state shared app-wide
```

**Use URL state for filters:**

```tsx
// app/tasks/page.tsx
import { Suspense } from 'react';
import { TaskList } from '@/components/TaskList/TaskList';
import { TaskFilters } from '@/components/TaskFilters';

interface PageProps {
  searchParams: { status?: string; page?: string };
}

export default async function TasksPage({ searchParams }: PageProps) {
  const status = (await searchParams).status || 'all';
  
  return (
    <Suspense fallback={<TaskListSkeleton />}>
      <TaskFilters currentStatus={status} />
      <TaskList initialPage={1} status={status} />
    </Suspense>
  );
}

// components/TaskFilters.tsx
'use client';

import { useRouter, useSearchParams } from 'next/navigation';
import { Select, SelectItem } from '@heroui/select';

export function TaskFilters({ currentStatus }: { currentStatus: string }) {
  const router = useRouter();
  const searchParams = useSearchParams();
  
  const updateFilters = (status: string) => {
    const params = new URLSearchParams(searchParams);
    params.set('status', status);
    router.push(`/tasks?${params.toString()}`);
  };
  
  return (
    <Select
      label="Filter by status"
      value={currentStatus}
      onChange={e => updateFilters(e.target.value)}
      className="max-w-xs mb-4"
    >
      <SelectItem key="all" value="all">All</SelectItem>
      <SelectItem key="active" value="active">Active</SelectItem>
      <SelectItem key="completed" value="completed">Completed</SelectItem>
    </Select>
  );
}
```

## Data Fetching Patterns

### React Query with Infinite Scroll (Recommended for Lists)

```tsx
// hooks/useTasks.ts
import { useInfiniteQuery } from '@tanstack/react-query';
import { fetchTasks } from '@/lib/api';

export function useTasks(status?: string) {
  return useInfiniteQuery({
    queryKey: ['tasks', status],
    queryFn: ({ pageParam = 1 }) => fetchTasks({ page: pageParam, limit: 10, status }),
    initialPageParam: 1,
    getNextPageParam: (lastPage, allPages) => {
      // If we got 10 items, there might be more
      return lastPage.length === 10 ? allPages.length + 1 : undefined;
    },
    staleTime: 5 * 60 * 1000, // 5 minutes
    gcTime: 30 * 60 * 1000,   // 30 minutes (formerly cacheTime)
  });
}

// lib/api.ts
export async function fetchTasks(params: { page: number; limit: number; status?: string }) {
  const searchParams = new URLSearchParams();
  searchParams.set('page', params.page.toString());
  searchParams.set('limit', params.limit.toString());
  if (params.status) searchParams.set('status', params.status);
  
  const res = await fetch(`${process.env.NEXT_PUBLIC_API_URL}/tasks?${searchParams}`);
  
  if (!res.ok) throw new Error('Failed to fetch tasks');
  return res.json();
}

// components/TaskList/TaskList.tsx - Usage example shown in Component Patterns section
```

## Form Handling

### React Hook Form with HeroUI Components

```tsx
// app/tasks/new/page.tsx
'use client';

import { useForm } from 'react-hook-form';
import { zodResolver } from '@hookform/resolvers/zod';
import { z } from 'zod';
import { Input } from '@heroui/input';
import { Textarea } from '@heroui/textarea';
import { Button } from '@heroui/button';
import { createTaskAction } from '@/app/actions';

const CreateTaskSchema = z.object({
  title: z.string().min(1, 'Title is required').max(200),
  description: z.string().max(2000).optional(),
});

type CreateTaskInput = z.infer<typeof CreateTaskSchema>;

export default function NewTaskPage() {
  const {
    register,
    handleSubmit,
    formState: { errors, isSubmitting },
  } = useForm<CreateTaskInput>({
    resolver: zodResolver(CreateTaskSchema),
  });

  const onSubmit = async (data: CreateTaskInput) => {
    await createTaskAction(data);
  };

  return (
    <form onSubmit={handleSubmit(onSubmit)} className="space-y-4 max-w-md">
      <Input
        {...register('title')}
        label="Title"
        placeholder="Enter task title"
        isInvalid={!!errors.title}
        errorMessage={errors.title?.message}
        isRequired
      />
      
      <Textarea
        {...register('description')}
        label="Description"
        placeholder="Enter task description"
        isInvalid={!!errors.description}
        errorMessage={errors.description?.message}
        minRows={4}
      />
      
      <div className="flex gap-2">
        <Button type="submit" color="primary" isLoading={isSubmitting}>
          Create Task
        </Button>
        <Button variant="bordered" type="button" href="/tasks">
          Cancel
        </Button>
      </div>
    </form>
  );
}

// app/actions.ts
'use server';

import { redirect } from 'next/navigation';
import { revalidatePath } from 'next/cache';

export async function createTaskAction(data: { title: string; description?: string }) {
  // Call your API or database
  const response = await fetch(`${process.env.API_URL}/tasks`, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify(data),
  });
  
  if (!response.ok) throw new Error('Failed to create task');
  
  revalidatePath('/tasks');
  redirect('/tasks');
}
```

## Design System Adherence

### Avoid the AI Aesthetic

| AI Default | Why It Is a Problem | Production Quality |
|---|---|---|
| Purple/indigo everything | Models default to visually "safe" palettes | Use the project's actual color palette |
| Excessive gradients | Adds visual noise | Flat or subtle gradients matching design system |
| Rounded everything (rounded-2xl) | Ignores hierarchy of corner radii | Consistent border-radius from design system |
| Generic hero sections | Template-driven, no content connection | Content-first layouts |
| Oversized padding everywhere | Destroys visual hierarchy | Consistent spacing scale |
| Stock card grids | Ignores information priority | Purpose-driven layouts |
| Shadow-heavy design | Competes with content | Subtle or no shadows unless specified |

### Spacing and Layout

Use a consistent spacing scale:

```css
/* Use the scale: 0.25rem increments */
/* Good */  padding: 1rem;      /* 16px */
/* Good */  gap: 0.75rem;       /* 12px */
/* Bad */   padding: 13px;      /* Not on any scale */
/* Bad */   margin-top: 2.3rem; /* Not on any scale */
```

### Typography

Respect the type hierarchy:

```
h1 → Page title (one per page)
h2 → Section title
h3 → Subsection title
body → Default text
small → Secondary/helper text
```

Don't skip heading levels. Don't use heading styles for non-heading content.

### Color

- Use semantic color tokens: `text-primary`, `bg-surface`, `border-default` — not raw hex values
- Ensure sufficient contrast (4.5:1 for normal text, 3:1 for large text)
- Don't rely solely on color to convey information (use icons, text, or patterns too)

## Accessibility (WCAG 2.1 AA)

Every component must meet these standards:

### Keyboard Navigation

```tsx
// Every interactive element must be keyboard accessible
<button onClick={handleClick}>Click me</button>        // ✓ Focusable by default
<div onClick={handleClick}>Click me</div>               // ✗ Not focusable
<div role="button" tabIndex={0} onClick={handleClick}    // ✓ But prefer <button>
     onKeyDown={e => {
       if (e.key === 'Enter') handleClick();
       if (e.key === ' ') e.preventDefault();
     }}
     onKeyUp={e => {
       if (e.key === ' ') handleClick();
     }}>
  Click me
</div>
```

### ARIA Labels

```tsx
// Label interactive elements that lack visible text
<button aria-label="Close dialog"><XIcon /></button>

// Label form inputs
<label htmlFor="email">Email</label>
<input id="email" type="email" />

// Or use aria-label when no visible label exists
<input aria-label="Search tasks" type="search" />
```

### Focus Management

```tsx
// Move focus when content changes
'use client';

import { useEffect, useRef } from 'react';

function Dialog({ isOpen, onClose }: DialogProps) {
  const closeRef = useRef<HTMLButtonElement>(null);

  useEffect(() => {
    if (isOpen) closeRef.current?.focus();
  }, [isOpen]);

  // Trap focus inside dialog when open
  return (
    <dialog open={isOpen}>
      <button ref={closeRef} onClick={onClose}>Close</button>
      {/* dialog content */}
    </dialog>
  );
}
```

```tsx
// Optimistic updates with React Query
'use client';

import { useMutation, useQueryClient } from '@tanstack/react-query';
import { Checkbox } from '@heroui/checkbox';

export function TaskItem({ task }: { task: Task }) {
  const queryClient = useQueryClient();
  
  const toggleMutation = useMutation({
    mutationFn: (taskId: string) => fetch(`/api/tasks/${task.id}/toggle`, { method: 'POST' }),
    onMutate: async () => {
      // Cancel outgoing refetches
      await queryClient.cancelQueries({ queryKey: ['tasks'] });
      
      // Snapshot the previous value
      const previousTasks = queryClient.getQueryData(['tasks']);
      
      // Optimistically update
      queryClient.setQueryData(['tasks'], (old: any) => ({
        ...old,
        pages: old.pages.map((page: any) => 
          page.map((t: Task) => 
            t.id === task.id ? { ...t, done: !t.done } : t
          )
        ),
      }));
      
      return { previousTasks };
    },
    onError: (err, variables, context) => {
      // Rollback on error
      queryClient.setQueryData(['tasks'], context?.previousTasks);
    },
    onSettled: () => {
      // Always refetch after error or success
      queryClient.invalidateQueries({ queryKey: ['tasks'] });
    },
  });

  return (
    <Checkbox
      isSelected={task.done}
      onValueChange={() => toggleMutation.mutate(task.id)}
      isDisabled={toggleMutation.isPending}
    >
      {task.title}
    </Checkbox>
  );
}
```

## Common Rationalizations

| Rationalization | Reality |
|---|---|
| "Accessibility is a nice-to-have" | It's a legal requirement in many jurisdictions and an engineering quality standard. |
| "We'll make it responsive later" | Retrofitting responsive design is 3x harder than building it from the start. |
| "The design isn't final, so I'll skip styling" | Use the design system defaults. Unstyled UI creates a broken first impression for reviewers. |
| "This is just a prototype" | Prototypes become production code. Build the foundation right. |
| "The AI aesthetic is fine for now" | It signals low quality. Use the project's actual design system from the start. |
| "Server Components are too complex" | They simplify data fetching and improve performance. Start with simple examples. |

## Red Flags

- Components with more than 200 lines (split them)
- Inline styles or arbitrary pixel values
- Missing error states, loading states, or empty states
- No keyboard navigation testing
- Color as the sole indicator of state (red/green without text or icons)
- Generic "AI look" (purple gradients, oversized cards, stock layouts)
- Client Components where Server Components would suffice
- Prop drilling deeper than 3 levels without context
- Using `use client` at the top of files unnecessarily
- Not using React Query for server state (fetching in useEffect)
- Manual pagination instead of useInfiniteQuery
- Not using HeroUI components consistently
- Mixing multiple UI libraries

## Verification

After building UI:

- [ ] Component renders without console errors
- [ ] All interactive elements are keyboard accessible (Tab through the page)
- [ ] Screen reader can convey the page's content and structure
- [ ] Responsive: works at 320px, 768px, 1024px, 1440px
- [ ] Loading, error, and empty states all handled
- [ ] Follows the project's design system (spacing, colors, typography)
- [ ] No accessibility warnings in dev tools or axe-core
- [ ] Server Components used where possible (data fetching, static content)
- [ ] Client Components only where interactivity is needed
- [ ] Forms have proper validation and error messages
- [ ] React Query configured correctly (query keys, staleTime, gcTime)
- [ ] Infinite scroll pagination implemented with useInfiniteQuery
- [ ] HeroUI components used consistently throughout
- [ ] Optimistic updates implemented for better UX where appropriate
